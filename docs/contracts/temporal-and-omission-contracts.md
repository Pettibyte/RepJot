# Temporal and omission contracts

Status legend and source abbreviations: see `docs/contracts/README.md`. These rules define when each persisted fact is created, frozen, or removed. Owner abbreviations: plan = execution-plan module (`src/sessions/execution-plan.ts`), session = session service, sem = semantic validator, score = score service, units = unit conversion module (`src/units/conversion.ts`). The first owner listed is primary; gates after `supporting:` are auxiliary and never co-own the rule.

## 2. Terminal omission states — evidence and discrimination

Persisted facts available to a terminal-session validator (status `completed` or `abandoned`): session fields (RS-03/04), every recorded result with full `executionPath`, direct IDs, statuses, `reasonCode`s (RS-06..11), the current static tree (FF-01/02). Not available: the workout tree as it existed at session start, and any record of work that was never entered.

| State | Definition | Persisted signature under conformant v1 writers | Distinguishable without inference? |
| --- | --- | --- | --- |
| S1 | Exercise deprecated and omitted when the session started. | A skipped result with `reasonCode: "deprecated"` at (or, for an emptied container, on) that path — created by TR-02 and retained after `executionPlan` removal. | Yes, by presence of the recorded skip. |
| S2 | Work existed but remained untouched before later deprecation. | No result at the path; the leaf is deprecated in the current tree. | Yes against S1 (no recorded skip). Behaviorally it must stay hidden and create no completeness or score violation (TR-12). |
| S3 | A nondeprecated node entered the workout tree after session completion. | No result at the path; the leaf is not deprecated in the current tree. | Distinguishable from S2 by the current deprecation flag. Behaviorally identical to plain untouched work: blank, editable node (TR-12). |
| S0 (baseline) | Present at start, nondeprecated, untouched. | No result at the path; leaf not deprecated. | Indistinguishable from S3 in persisted data; required behavior is identical (blank, editable). |

Consequences of approved Option A (D-01):

- The v1 writer contract (TR-02) already persists an omission marker that survives `executionPlan` removal: the `reasonCode: "deprecated"` skip. S1 vs S2 therefore discriminate on persisted evidence; missing results never prove omission in either direction.
- S3 vs S0 cannot be discriminated from persisted data, and Option A adds no storage to change that; both are blank, editable nodes. If the product owner later requires the distinction, a new approved contract change must supply the fact (former options B/C).
- A scored container's detail-only status after completion is derivable only from descendant recorded deprecated skips. Terminal validation treats a container with no such evidence as an ordinary scored container: unclassified for omission, never requiring `nonstandard` on historical data.
- Non-conformant or hand-edited documents (a missing S1 skip) cannot be reconciled by any design without a tree snapshot; first release ships no pre-v1 user data. Approved policy: display-only — such documents are shown per current rules and never rejected for a fact that cannot be proven.

## 4. Input and persisted facts

| Rule | Required input facts | Required persisted facts |
| --- | --- | --- |
| TR-01 | Workout deprecation flags, secure random source, browser clock instant. | `startedAtUtc` + shard filename (persisted-facts §1 Session start instant and shard). |
| TR-02 | The effective workout tree at start + deprecated exercises. | `executionPlan` while active; the `reasonCode: "deprecated"` skips survive plan removal (persisted-facts §1 Deprecated-at-start omission). |
| TR-03 | The pending shard content. | Local IndexedDB shard committed before navigation. |
| TR-04 | The frozen `executionPlan` after reload. | Plan removed exactly on the terminal transition; `endedAtUtc` set (persisted-facts §1 Active-session effective tree). |
| TR-05 | Recorded results + current static tree. | None new — no terminal `executionPlan` is persisted (ADR-020). |
| TR-06 | Entered, blurred, or default-presented values. | Full-precision converted values, or nothing for never-entered fields. |
| TR-07 | Unsaved local edits at navigation. | The `in_progress` save; a permanent tombstone on deletion (RS-15). |
| TR-08 | The session's start UTC month. | The original shard only; no second shard is written by corrections. |
| TR-09 | The final preference candidate of one synchronization. | `revision`, `updatedAtUtc` changed exactly once. |
| TR-10 | Entered value + source and target units. | Full-precision converted (or user-entered) number. |
| TR-11 | Last successful reconciliation time + remote metadata. | Cached Drive metadata (persisted-facts §1 Change indicators for remote files). |
| TR-12 | Recorded `reasonCode: "deprecated"` skips + current deprecation flags (persisted-facts §1 Deprecated-at-start omission). | None — Option A adds no storage and changes no results schema (D-01; persisted-facts §2). |
